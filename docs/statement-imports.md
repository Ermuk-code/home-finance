# Импорт банковских выписок

Веб и Telegram используют один сервис `app/finance/services/statement_imports.py`.
Рабочая последовательность: загрузить файл → проверить предпросмотр → сохранить операции.
До подтверждения финансовая история не меняется. Предпросмотр хранится в PostgreSQL,
а не в памяти бота; его можно открыть после перезапуска.

## Как пользоваться

1. Откройте `/upload`, выберите PDF/CSV. Для CSV при необходимости укажите банк.
2. Укажите постоянную метку счёта, если номер не извлекается из файла. Для одного счёта
   используйте одну метку во всех форматах выгрузки; для разных счетов — разные.
3. Проверьте новые операции и совпадения. Для каждой спорной строки выберите «добавить»
   либо «пропустить». Для одного банковского номера с разными данными доступен только пропуск;
   проверьте исходные документы перед исправлением существующей операции.
4. Нажмите «Сохранить операции». В истории можно открыть результат или отменить импорт.

В Telegram отправьте документ. Если спорных строк нет, сохраните кнопкой в сообщении.
Иначе откройте предложенную веб-страницу и разберите совпадения там. Для входа используйте
`/web`; для возврата к предыдущим загрузкам — `/imports`. Брокерские отчёты работают как раньше
и сохраняются немедленно; история и отмена этого раздела относятся к банковским выпискам.

## Идентичность и неоднозначность

- SHA-256 исходного файла защищает от повторной загрузки в пределах пользователя и введённой
  метки счёта. Активный файл имеет одну загрузку; отменённый можно загрузить снова.
- CSV сохраняет текстовые номера счетов и операций без преобразования в float и потери ведущих
  нулей. Распознаются явно названные колонки идентификатора/номера операции и референса проводки.
  «Код операции» не считается уникальным номером: он может обозначать тип платежа.
- Для PDF извлекается однозначный 20-значный номер счёта с явной меткой в заголовке.
  Банковские номера, которых нет в документе, не придумываются.
- По банковскому номеру в том же банке и счёте точный повтор пропускается автоматически.
  Совпавший номер с изменившимися данными показывается как конфликт, без перезаписи истории.
- Без номера операции совпадение полного описания, времени и суммы с имеющейся записью требует
  решения пользователя. Одинаковые строки внутри нового файла сохраняются раздельно; если файл
  содержит больше одинаковых покупок, чем есть в базе, дополнительные экземпляры считаются новыми.
- Изменённое описание или неизвестный счёт у старой операции не приводят к молчаливому удалению:
  показываются кандидаты с тем же банком и суммой в пределах 24 часов. Для каждой строки
  показывается до пяти кандидатов. Это эвристика для ручной проверки, не доказательство дубля.
- Время без часового пояса считается московским, хранится в UTC. Полное описание сохраняется.
  Для сравнения нормализуются только Unicode, регистр и пробелы; первые 40 символов не используются.

Приложение не может гарантированно распознать одну операцию при одновременно изменённых дате,
сумме и описании и отсутствии банковского номера. Для таких документов проверяйте предпросмотр
и итоговое количество операций. Старые записи миграция не пересчитывает и не очищает автоматически.

## Сохранение и отмена

Подтверждение повторно проверяет совпадения под блокировкой строки владельца (`FOR UPDATE`).
Изменившийся предпросмотр возвращает 409: интерфейс предлагает актуальные данные для новой проверки.
Все строки и статус сохраняются одной транзакцией. Повторное подтверждение уже сохранённой загрузки
возвращает прежние счётчики. Уникальные ограничения в БД дополнительно защищают идентификаторы.
Разные одинаковые покупки без банковских номеров получают отдельные порядковые вхождения.

Отмена помечает загрузку `reverted` и удаляет связанные импортированные операции, на которые
больше не ссылается ни одна сохранённая загрузка. Ручной ввод и записи до этой миграции не удаляются.
Если одна операция встречалась в двух загрузках, она остаётся до отмены последней использующей
её загрузки. Поэтому отмена последней может удалить операцию, первоначально созданную первой.
Ручная правка категории импортированной операции не отменяет её происхождение: при отмене
операция вместе с правкой может быть удалена. Это указано перед действием в веб-интерфейсе.
Источник, текст строки и результат обработки остаются в истории; повторная отмена безопасна.

## Обновление и проверка

Нужна миграция `9e0c3f6a2b71`: `alembic upgrade head`. Docker entrypoint выполняет её автоматически
при обновлении образа. Обычная команда обновления: `docker compose up -d --build`.
До миграции новый код запускать нельзя. Миграция добавляет таблицы/поля и не объединяет старые записи.

`tests/test_statement_imports.py` проверяет реальное сохранение на изолированной SQLite,
HTTP-права, Telegram, неоднозначные совпадения, атомарность и отмену.
`tests/test_statement_imports_postgres.py` проверяет параллельные загрузки/подтверждения и целевую БД.
Эти проверки включаются только явной переменной `TEST_POSTGRES_URL` с адресом одноразовой тестовой
PostgreSQL. Не указывайте в ней рабочую базу. CI создаёт отдельный PostgreSQL 16, проверяет upgrade,
downgrade новой миграции и повторный upgrade, затем запускает тесты.
