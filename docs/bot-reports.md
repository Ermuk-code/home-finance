# Кнопочное меню и отчеты с графиками

После обновления отправьте боту `/start`. Постоянное нижнее меню содержит четыре кнопки:
«📊 Финансы (Отчет)», «⚖️ Здоровье и Питание», «🏋️ Тренировка на сегодня»,
«⚙️ Команды и Настройки». Прежние команды сохранены; прежние подписи основных кнопок
отчетов/тренировок также принимаются. Клавиатуры вынесены в пакет `app/bot/keyboards/`;
старые импорты из `app.bot.keyboards` продолжают работать.

В финансах и здоровье доступны «За сегодня», «За месяц», «За год», «Выбрать период».
Месяц/год — текущий календарный месяц/год **до сегодняшнего дня**, а не последние 30/365 дней.
Границы дней задаются `ACTIVITY_TZ` (по умолчанию Europe/Moscow), финансовые операции
выбираются по диапазону `[начало суток; начало следующих суток после конца периода)`.

Произвольные даты вводятся как `ДД.ММ.ГГГГ-ДД.ММ.ГГГГ`, например `01.11.2026-16.11.2026`.
Допускаются пробелы и длинное тире. Неверная дата, перевернутый диапазон, будущий конец
или период длиннее 366 дней возвращают понятную ошибку, состояние ввода сохраняется.
Кнопка «Отмена», основные разделы меню и `/cancel` позволяют выйти из ввода.
FSM хранится в памяти процесса, после перезапуска период нужно выбрать заново.

В разделе финансов есть кнопки наличных, ручной операции, лимитов, вклада и портфеля.
В здоровье — веса, активности, питания, недельной сводки, прогноза процента жира и FatSecret.
В настройках — дополнительные команды и кнопки веб-панели, PDF портфеля, разбора операций,
связи/отвязки FatSecret; для admin — аналитика пользователей.
Callback передает исходного пользователя обработчику, а не Telegram ID самого бота.
Сессия БД и авторизация продолжают поступать из `DbSessionAndAuthMiddleware`.

Кнопка сегодняшней тренировки использует существующие `workouts` и `workout_exercises`:
внутренний `users.id` определяется по Telegram ID, затем читается только личный план.
У незавершенной тренировки есть Inline-кнопка «✅ Завершить». При отсутствии плана:
«На сегодня тренировок не запланировано. Отдыхаем! 🛋».

## Изображения отчетов

`app/services/reporting.py` готовит данные и текст для выбранного пользователя и периода.
Финансы учитывают возвраты и исключают переводы между своими счетами из чистых итогов.
Здоровье использует `HealthAnalytics` с прежней обработкой пропусков и неполных дней.

`app/services/screenshot.py::take_dashboard_screenshot(start_date, end_date, token, report_type)`
возвращает PNG. Асинхронный Playwright запускает Chromium, открывает локальную страницу,
дожидается `networkidle` и явного признака завершения отрисовки Chart.js, снимает блок отчета
и закрывает браузер в `finally`. Генерация ограничена одним браузером одновременно и общим
таймаутом 60 секунд. Повторный запрос того же пользователя во время генерации не создает второй отчет.

Страница `/dashboard-render` содержит крупные шрифты, контрастные карточки и два графика без меню.
Chart.js 4.5.1 и лицензия поставляются локально в `app/web/static/vendor`, внешние CDN не нужны.
Финансовый снимок: доходы/расходы/итог, расходы по категориям и динамика по дням.
Снимок здоровья: средние показатели, питание/расход/вес и шаги.

Бот отправляет `BufferedInputFile` через `answer_photo`. Если подпись превышает 1000 символов,
под фото остается короткая подпись, а полная сводка отправляется отдельным сообщением.
При недоступном браузере или ошибке доставки фото остается текстовый отчет.
Доставка сообщений в Telegram во время автоматических тестов подменяется; тесты не рассылают пользователям отчеты.

## Защита страницы

Страница не доступна по обычной cookie, access JWT или общему webhook-токену.
Для нее создается отдельный JWT типа `dashboard_render` сроком 2 минуты, привязанный
к `user_id`, типу отчета и обеим датам. Подмена периода или типа дает 401.
Пользователь берется из токена; произвольный `user_id` в URL не меняет область данных.
Удаленный из БД профиль теряет доступ. Токен отчета не дает обычную веб-сессию и не принимается API пользователя.

Генератор передает токен в **Authorization**, а не в URL, чтобы он не попадал в access log.
Query-параметр `token` поддерживается для совместимости с ТЗ, но для штатной генерации не используется.
Ответ страницы имеет `Cache-Control: no-store` и `Referrer-Policy: no-referrer`.
Браузеру разрешены только запросы к `127.0.0.1:8000`, чтобы не передавать токен внешним сайтам.
Не публикуйте временные ссылки вручную. В логах ошибок генератора выводится тип ошибки, а не JWT/URL.

## Docker и обновление

`requirements.txt` закрепляет `playwright==1.65.2`. Dockerfile устанавливает `libatomic1`
(для запуска встроенного Node в python:3.12-slim), затем Chromium с системными зависимостями.
`PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`; браузер доступен непривилегированному пользователю приложения.

```bash
docker compose up -d --build app
```

Первая сборка скачивает браузер и может занять несколько минут. Новых переменных `.env`
и миграций для этого спринта нет. Веб-сервер и бот должны оставаться в текущем едином контейнере:
генератор обращается к `http://127.0.0.1:8000`.
