# Прогноз по проценту жира

## Использование

На странице «Здоровье» выберите профиль. В форме «Добавить замер» внесите **вес и процент жира
одного измерения**. В «Профиль и цель» задайте целевой процент и средний ежедневный дефицит,
затем сохраните профиль. По умолчанию это 12% и 500 ккал/день; это параметры модели, а не назначение.
Блок «Прогноз по проценту жира» и команда бота `/abs_forecast` показывают один расчет.
Кнопка «💪 Прогноз пресса» появляется в меню после `/start` или `/help`.

Для Home Assistant обновлен шаблон `homeassistant/rest_command.yaml`:
`rest_command.send_weight_to_life_os` дополнительно принимает `body_fat` в процентах.
Передавайте его только из того же измерения, что и вес. Пример:

```yaml
service: rest_command.send_weight_to_life_os
data:
  profile: admin
  weight: 81.55
  body_fat: 18.0
```

Backend принимает `POST /api/health/webhook/weight` с прежним `X-Webhook-Token`:
`{"profile_alias":"admin","weight_kg":81.55,"body_fat":18.0}`.
Также принимается имя `body_fat_percent`. Старые запросы только с весом продолжают работать.
Процент проверяется: >0 и <100, не более одного десятичного знака. При ручном вводе он требует вес.
Из роста/талии процент автоматически не выдумывается.

## Данные и API

Миграция `6c8a1f4e0d32` добавляет `users.target_body_fat` (12), `users.avg_daily_deficit` (500)
и nullable `weight_logs.body_fat`. `HealthMetric` — совместимое имя существующего `WeightLog`:
`weight` соответствует `weight_kg`, `date` — `timestamp`. `User.height` ссылается на `height_cm`;
рост владельца по-прежнему инициализируется 184 см. История веса не копируется в отдельную таблицу.

`GET /api/v1/health/forecast-abs` требует cookie/Bearer авторизацию, по умолчанию свой профиль.
`?user_id=4` доступен администратору; обычный пользователь не может получить чужой прогноз (403).
Несуществующий пользователь — 404, некорректный id — 422.
Telegram делает запрос к этому API по loopback с токеном своего пользователя, а не Telegram ID из сообщения.

Параметры меняются через `PATCH /api/health/profile?target_user_id=…`:
`{"target_body_fat":12,"avg_daily_deficit":500}`. Поля валидируются, дефицит — целое 0–2000.
Автоматической записи среднего дефицита из FatSecret здесь нет: используется явно заданный параметр,
независимый от процентного дефицита плана питания. Источник отражен в `deficit_source="configured"`.

Response Model `AbsForecastResponse` возвращает:
`current_weight`, `current_body_fat`, `target_body_fat`, `avg_daily_deficit`, `deficit_source`,
`target_weight`, `fat_mass`, `lean_body_mass`, `fat_to_lose`, `total_deficit_needed`,
`days_left`, `target_date`, `metric_at`, `status`, `warnings`, `model_note`.

Выбирается последний **парный замер с процентом жира**, не позже текущего времени.
Вес из более позднего замера без процента не смешивается со старым процентом жира.
`metric_at` показывает дату и часовой пояс исходных данных; замер старше 14 дней отмечается предупреждением.

## Математика

1. `fat_mass = weight × body_fat / 100`
2. `lean_body_mass = weight − fat_mass`
3. `target_weight = lean_body_mass / (1 − target_body_fat / 100)`
4. `fat_to_lose = max(0, weight − target_weight)`
5. `total_deficit_needed = fat_to_lose × 7700`
6. `days_left = ceil(total_deficit_needed / avg_daily_deficit)`
7. `target_date = today(ACTIVITY_TZ) + days_left`

Дни считаются по неокругленным промежуточным значениям, дробный день округляется **вверх**.
Пример: 81.55 кг, 18%, цель 12%, дефицит 500 → 75.99 кг, 86 дней;
при расчете 16.11.2026 дата — 10.02.2027.

Статусы (HTTP 200, ожидаемые состояния, не ошибки сервера):

* `in_progress`: есть положительный дефицит и замер, дата рассчитана.
* `achieved`: целевой процент >= текущего, 0 дней, дата сегодня (даже при нулевом дефиците).
* `missing_metrics`: нет парного замера, значения и дата отсутствуют.
* `no_deficit`: дефицит <=0, дата и срок отсутствуют.
* `horizon_exceeded`: срок выходит за диапазон `datetime.date`, дата отсутствует.

## Ограничения

Это статическая математическая модель, предполагающая постоянные сухую массу и дефицит.
Она не предсказывает видимость пресса, изменения мышц и воды, адаптацию расхода или точность весов.
12% не является универсальной целью: для женщин при цели <=12% отображается отдельное предупреждение.
Индивидуальную цель следует согласовывать с учетом здоровья и обстоятельств; формулировки бота
не обещают «увидеть пресс» к указанной дате и не предписывают конкретные продукты.

Основания для оговорок: [NIDDK Body Weight Planner](https://www.niddk.nih.gov/bwp),
[позиция NATA о составе тела и контроле массы](https://pmc.ncbi.nlm.nih.gov/articles/PMC3419563/).
