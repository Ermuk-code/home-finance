# Календарь тренировок

Откройте `/workouts` через пункт «Тренировки» в навигации. На странице — текущая неделя
(понедельник–воскресенье), переходы между неделями, выбор профиля и карточки дней.
Обычный пользователь видит и меняет свои планы; admin может выбрать другой профиль.

«Добавить тренировку» открывает форму с датой, названием и динамическим списком упражнений:
название, подходы, повторения (строка: `10-12`, `до отказа`, `30 секунд`) и необязательный рабочий вес.
Можно добавить несколько тренировок на одну дату. Каждая имеет собственную отметку выполнения.
Ошибки валидации остаются в модальном окне; неудачная отправка не закрывает введенные данные.
Удаление плана требует подтверждения в браузере и удаляет его упражнения.

## API

Все маршруты требуют cookie/Bearer авторизацию и используют `get_scope`.
У admin по умолчанию свои данные; для другого профиля нужен `?target_user_id=…`.
Чужая тренировка без разрешенной области возвращает 404, запрещенный выбор профиля — 403.

* `GET /api/health/workouts` — текущая неделя по `ACTIVITY_TZ`.
  Необязательные `start_date`, `end_date` задают включительный период до 366 дней.
  Admin может читать `all_users=true`; каждая запись содержит владельца `user_id`.
* `POST /api/health/workouts` — один план с массивом вложенных упражнений, HTTP 201.
  Для создания нужно выбрать один профиль; `all_users=true` не разрешен.
* `PATCH /api/health/workouts/{id}/complete` — идемпотентная отметка выполнения.
* `DELETE /api/health/workouts/{id}` — HTTP 204, удаление вместе с упражнениями.
* `GET /api/health/workouts/next` — ближайший невыполненный план, включая сегодня, или `null`.
  Используется плашкой на главном финансовом дашборде.

Пример создания:

```json
{
  "date": "2026-11-17",
  "title": "День ног",
  "exercises": [
    {"name": "Приседания", "sets": 3, "reps": "10-12", "weight_kg": 50.5},
    {"name": "Планка", "sets": 2, "reps": "30 секунд"}
  ]
}
```

Ограничения: название плана 1–120 символов; 1–20 упражнений;
название упражнения 1–100, подходы — целое 1–100, повторения 1–40 символов,
вес 0–999.99 кг или null. Пробелы по краям удаляются; пустые строки и некорректные даты дают 422.
Прошедшие даты разрешены для учета истории. Редактирования состава уже сохраненного плана пока нет:
можно удалить план и создать новый. Выполненное не используется для оценки расхода калорий.

## Telegram и расписание

`/workout` или «🏋️ Тренировка на сегодня» показывает все личные планы на сегодня.
В карточке невыполненной тренировки и в утреннем напоминании есть кнопки «✅ Завершить» и «📅 Перенести».
Если день уже прошёл, откройте «Пропущенные тренировки» через `/workout` и выберите тренировку.
Можно нажать «Завтра», выбрать «Сегодня» для пропущенной тренировки или ввести дату в формате `ДД.ММ.ГГГГ`.
Чтобы отменить выбор даты, отправьте `/cancel`.

Перенос меняет дату в календаре и сохраняет все упражнения. Утреннее напоминание отправляется
по расписанию новой даты. Если перенести тренировку на сегодня после утренней рассылки,
она сразу появится в `/workout`. Бот проверяет владельца и актуальность карточки при каждом действии.

`send_morning_workout_plan` запускается APScheduler в **08:00 по `ACTIVITY_TZ`** (по умолчанию Москва).
Каждая сегодняшняя невыполненная тренировка отправляется только своему владельцу.
Успешная отправка записывается в `morning_notified_on`; повторный вызов задачи в тот же день
не шлет то же напоминание. Ошибка Telegram не отмечается как доставка и не прерывает остальные планы.
Пропущенный запуск догоняется в течение 30 минут. Тренировки, созданные позже утреннего запуска,
можно посмотреть командой `/workout`; отдельного повторного дневного пуша нет.

Задача работает в существующем единственном процессе приложения; строки при рассылке блокируются
через `FOR UPDATE SKIP LOCKED`, параллельные вызовы одной задачи ограничены `max_instances=1`.
При аварийном завершении между приемом сообщения Telegram и коммитом отметки возможен повтор:
транзакция БД не может атомарно охватить внешний Telegram API.

## База и запуск

Миграция `8d9b2a5f1e43` создает `workouts`, `workout_exercises`, индексы и ограничения.
`User.workouts ↔ Workout.user`, `Workout.exercises ↔ WorkoutExercise.workout`;
удаление владельца/плана каскадно удаляет подчиненные записи.
Запуск: `docker compose up -d --build app`; миграции выполняет существующий entrypoint.
Утреннюю задачу не нужно включать отдельным флагом. После обновления меню бота вызовите `/start`.

Тренировки не прибавляют калории к HA: активные калории часов уже могут включать тренировку,
а второй расчет привел бы к двойному учету. Связь тренировки с фактической активностью можно добавить отдельно.
