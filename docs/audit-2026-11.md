# Аудит проекта — 14.11.2026

## Стадия проекта

**Финансы — рабочий MVP, близкий к «готово для себя».** Есть разбор выписок трёх банков, автокатегоризация,
ручной ввод и наличные, лимиты, доходы по источникам, вклады, брокерский портфель с MOEX, PDF, напоминания,
недельная сводка, веб-дашборд и бот. Есть роли (admin/user) и изоляция данных.

**Здоровье — ранняя стадия (~25%).** Есть приём веса из Home Assistant и выгрузка КБЖУ из FatSecret.
Нет: целей (вес/калории), расчёта нормы (BMR/TDEE), веб-страниц, графиков, ручного ввода веса в боте,
источника данных для `activity_logs`.

**Заметки — отсутствуют. Напоминания** есть, но живут внутри финансового домена.

**Инфраструктура — недавно прошёл большой рефакторинг** (переезд в пакет `app/`, роли, `user_id` везде), но
старый код не удалён, бэкапов нет, CI нет.

## Проблемы

Приоритет: 🔴 — исправить в первую очередь, 🟠 — важно, 🟡 — желательно.

### ✅ 1. Две копии кода в репозитории
`bot/`, `services/`, `web/`, `db/` (вместе с `db/migrations/migrations/`), корневые `main.py` и `config.py` —
устаревшая версия до рефакторинга. Ничего из `app/` их не импортирует, `entrypoint.sh` запускает `app.main`.
Старый `main.py` вообще сломан (две функции `lifespan`, `Base.metadata.create_all` в обход Alembic).
Файлы уже разошлись с `app/` (`categorizer`, `scheduler`, `advisor` и др. отличаются) — правки легко внести не туда.
**Что сделать:** удалить эти каталоги и файлы одним коммитом.

### ✅ 2. XSS на страницах веб-панели
Часть данных вставляется через `innerHTML` без экранирования:
* `reminders.html:80,84` — `r.title`, `r.description`;
* `index.html:428` — название отпуска `v.name`;
* `index.html:582` — `item.ticker`, `item.name` (приходят из брокерского отчёта — внешний файл);
* `index.html:615,620` — тексты находок/советов;
* `upload.html:46,60` — название банка и тикеры из разобранного файла.

В других шаблонах уже есть `esc()`/`escapeHtml()` — нужно применить везде (лучше вынести одну функцию в `base.html`).

### ✅ 3. Напоминание с `<` или `&` в тексте «зависает»
`scheduler.check_reminders` шлёт `title`/`description` с `parse_mode="HTML"` без `html.escape`. Telegram
отвечает ошибкой, напоминание остаётся `is_notified=False` и повторно падает **каждую минуту** без конца.
**Что сделать:** экранировать текст; после N неудачных попыток помечать напоминание и логировать.

### ✅ 4. Нет резервного копирования БД
Все финансовые данные — в одном томе `pgdata`. Нужен ежедневный `pg_dump` с ротацией и копией вне LXC
(NAS / облако). Сделано — см. [deployment.md](deployment.md#5-бэкапы); **копию вне LXC нужно настроить вручную**.

### ✅ 5. Docker-сборка
* Нет `.dockerignore` → в образ попадают `.env` (секреты), `.git`, тесты, старый код.
* `volumes: - .:/app` в `docker-compose.yml` — образ фактически не используется, код берётся с хоста.
  Для прода убрать (оставить в `docker-compose.override.yml` для разработки).
* Зависимости не закреплены (`>=` без верхней границы) — пересборка может внезапно подтянуть aiogram 4 /
  SQLAlchemy 3. Нужен lock-файл (`pip-compile`/`uv`) или точные версии.
* Контейнер работает от root; нет `HEALTHCHECK` для app.

### 🟠 6. Вход в веб-панель
* Ссылка `/web` названа одноразовой, но JWT можно использовать сколько угодно раз в течение 5 минут.
  Нужно хранить `jti` использованных токенов (таблица или память).
* Нет ограничения попыток на `POST /api/login` — пароль admin можно перебирать.
* Отзыв сессий невозможен (JWT на 7 дней без серверного списка), смена `JWT_SECRET_KEY` разлогинит всех.

### 🟠 7. Структура домена
* В `app/web/pages.py` смешаны HTML-страницы и бизнес-API (вклады, активы, портфель, дашборд) — перенести в
  `app/finance/api/deposits.py`, `assets.py`, `dashboard.py`.
* `Reminder` в финансовом домене, хотя нужен для заметок/здоровья — вынести в отдельный домен `planner`.
* Модель `Deposit` не имеет связи `user` (у остальных есть) — мелочь, но непоследовательно.

### 🟠 8. Целостность данных
* Нет уникального индекса `assets(user_id, ticker)` — при гонке/двойной загрузке появятся дубли, и
  `scalar_one_or_none()` в `POST /api/assets` упадёт с 500.
* Дубли транзакций отсекаются только в Python (по дате+сумме+банку+40 символам описания); в БД ограничения нет.
* `GET /api/dashboard-stats` вызывает `seed_default_categories` (запись в БД) на каждый запрос.

### 🟠 9. Тесты
Состояние на 14.11.2026: `pytest` — **188 passed** (Python 3.12, свежие зависимости: pandas 3.1, SQLAlchemy 2.1).
Только unit-тесты без БД. Нет тестов API (FastAPI `TestClient`), нет проверки «модели == миграции»
(`alembic check`). CI добавлен на этапе 0. Тест цепочки миграций хардкодит голову — его надо править
при каждой миграции.

### 🟡 10. Мелочи
* Питание: записи, добавленные в FatSecret после 23:50, за прошедший день уже не синхронизируются —
  в 07:00 стоит дополнительно обновлять вчерашний день.
* MOEX запрашивается при каждом открытии дашборда — нужен кеш на 5–15 минут.
* `datetime.now()` без таймзоны в `admin.py`, `base.py` (работает только потому, что контейнер в UTC).
* Даты фильтра дашборда трактуются как UTC, а не как местное время.
* FSM бота в памяти — диалоги теряются при рестарте (можно `RedisStorage` или хранить в Postgres).
* Нет ограничения размера загружаемого файла на `/api/upload`.
* Токены FatSecret хранятся в БД в открытом виде (для домашнего сервиса допустимо, но стоит знать).
* `homeassistant/` и README ссылаются на `finance_app`/`finance_db` — после ребрендинга в Life OS можно переименовать.
